# Excel Reader

`Excel Reader` 插件实现了从 Microsoft Excel 文件读取数据的能力。

## 配置

## 参数说明

| 配置项     | 是否必须 | 类型        | 默认值 | 描述                                              |
| :--------- | -------- | ----------- | ------ | ------------------------------------------------- |
| path       | 是       | string/list | 无     | 指定要读取的文件夹，可以指定多个                  |
| header     | 否       | boolean     | false  | 文件是否包含头                                    |
| skipRows   | 否       | int         | 0      | 要跳过前多少行                                    |
| sheetIndex | 否       | int         | 0      | 要读取的 sheet 序号，从 0 开始                    |
| sheetName  | 否       | string      | 无     | 要读取的 sheet 名称，不要和 `sheetIndex` 同时使用 |
| trim       | 否       | boolean     | true   | 是否去除字符串单元格两端的空白                    |

### header

Excel 文件是否包含头，如果包含，则跳过

### skipRows

指定要跳过的行数， 默认为 0，表示不跳过。这里要注意的是，假定 设置了 `header` 为 true，同时设置 `skipRows` 为 2。则表示前三行都跳过。
如果 `header` 为 false， 则表示跳过前两行。

### sheetIndex / sheetName

默认只读取第一个 sheet，`sheetIndex` 从 0 开始计数，`sheetName` 按名字指定，两者不要同时设置。
当文件包含多个 sheet 而作业没有指定时，插件会输出一条告警，说明只读取了哪一个。

### trim

是否去除文本单元格两端的空白，默认为 `true`。Excel 中的文本经常带有肉眼看不见的空格，
默认会一并去掉；需要保留原始文本时设置为 `false`。

去除的是 Unicode 空白；不换行空格（`U+00A0`）属于字符而不是空白，两种设置下都会保留。

### 空值与公式

- 没有值的单元格——空白、空字符串、错误值（`#DIV/0!` 之类）以及被跳过的单元格——都读取为 `NULL`，不会是空字符串
- 每条记录的列数与最宽的一行对齐，中间缺失的单元格补 `NULL`，因此列不会错位
- 公式单元格读取的是 Excel 保存在文件里的计算结果。如果文件由程序生成（openpyxl、POI 等）而没有保存结果，公式列会读成 `NULL` 并给出告警，用 Excel 打开并保存一次即可
- 列数以表头行（`header` 为 `true` 时）或第一个数据行为准，后续更宽的行会按实际列数输出并告警一次

### 支持的数据类型

Excel 读取功能的实现依赖于 [Apache POI](https://poi.apache.org/) 项目，该实现对单元格的数据类型定义很宽泛。
仅定义了布尔型(Boolean)，数值型 (Double)，字符串型(String) 三种。其中数值型包括所有整数，小数和日期。
目前对于数值类型做了简单区分

1. 使用库工具类探测是否为日期类型，如果是，则判断为日期类型
2. 将数值转换为长整形，并和原值比较，如果大小相等，则判断为长整型(Long)
3. 否则判断为浮点型（Double）

## 内存占用

`xlsx` 采用流式读取，只保留正在处理的一行，内存占用与文件大小无关；`xls` 因为格式本身
限制（最多 65536 行）采用一次性载入，内存占用有上限。

## 限制

1. 暂不支持指定列读取
2. 暂不支持跳过尾部行数（比如有总结的尾行可能并不符合要求）
3. 不支持加密（口令保护）的工作簿，遇到会直接报错
4. 目录下的文件按内容识别（ZIP / OLE2 魔数），不是 Excel 的文件会被跳过并给出告警；
   后缀不对但内容是工作簿的文件同样能读取

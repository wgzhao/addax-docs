# Iceberg Writer

Iceberg Writer provides the ability to write data to an existing Iceberg table.

## Configuration Example

<<<@/public/assets/jobs/icebergwriter.json

The warehouse in the example above uses `s3a://`; the plugin already bundles the dependencies this protocol requires, so it can run directly. The default template generated by `addax.sh gen` uses the local filesystem.

## Parameters

| Configuration | Required | Data Type | Default Value | Description                                                                                                |
| :------------ | :------: | --------- | ------------- | ---------------------------------------------------------------------------------------------------------- |
| tableName     |   Yes    | string    | None          | Name of the Iceberg table to write                                                                         |
| catalogType   |   Yes    | string    | None          | Catalog type, currently supports hive, hadoop                                                              |
| warehouse     |   Yes    | string    | None          | Warehouse address                                                                                          |
| writeMode     |   Yes    | string    | None          | Write mode, detailed below                                                                                 |
| hadoopConfig  |    No    | json      | {}            | Can configure some advanced parameters related to the Iceberg catalog and Hadoop, such as HA configuration |

### writeMode

Data cleanup mode before writing:

- append: no processing before writing, write directly without clearing the original data.
- truncate: clear the table before writing, then write.

### hadoopConfig

`hadoopConfig` can configure some advanced parameters related to the Iceberg catalog and Hadoop, such as HA configuration

This option can be left empty, in which case the hadoop configuration on the classpath is used (that is, the default values of `core-site.xml` and the like).

### Using the s3a protocol (S3 / MinIO)

`s3a://` works out of the box: the plugin bundles `hadoop-aws` and the AWS SDK v1 modules it actually uses (about 6 MB), but not the 297 MB `aws-java-sdk-bundle`. Write the warehouse directly as `s3a://...` and configure `fs.s3a.*` in `hadoopConfig` as described in the "s3 or minio hadoop catalog example" below.

Create an Iceberg table stored in minio with catalogType hadoop

```java
package com.test;
import org.apache.hadoop.conf.Configuration;
import org.apache.iceberg.hadoop.HadoopCatalog;
import org.apache.iceberg.Table;
import org.apache.iceberg.catalog.TableIdentifier;
import org.apache.iceberg.Schema;
import org.apache.iceberg.types.Types;

import java.io.IOException;

public class CreateMinioTable {
    public static void main(String[] args) throws IOException {

        Configuration hadoopConf = new Configuration();
        "fs.s3a.endpoint", "http://localhost:9000");
        "fs.s3a.access.key", "gy0dX5lALP176g6c9fYf");
        "fs.s3a.secret.key", "ReuUrCzzu5wKWAegtswoHIWV389BYl9AB1ZQbiKr");
        "fs.s3a.connection.ssl.enabled", "false");
        "fs.s3a.path.style.access", "true");
        "fs.s3a.impl","org.apache.hadoop.fs.s3a.S3AFileSystem");
        String warehousePath = "s3a://pvc-91d1e2cd-4d25-45c9-8613-6c4f7bf0a4cc/iceberg";
        HadoopCatalog catalog = new HadoopCatalog(hadoopConf, warehousePath);

        TableIdentifier name = TableIdentifier.of("test", "test1");

        Schema schema = new Schema(
                Types.NestedField.required(1, "id", Types.IntegerType.get()),
                Types.NestedField.required(2, "ts1", Types.TimestampType.withoutZone()),
                Types.NestedField.required(3, "name", Types.StringType.get())
        );
        Table table = catalog.createTable(name, schema);
        System.out.println(table.location());

        catalog.close();
    }
}
```

## Type Conversion

| Addax internal type                    | Iceberg data type |
| -------------------------------------- | ----------------- |
| Integer                                | INTEGER           |
| Long                                   | LONG              |
| Double                                 | DOUBLE            |
| Float                                  | FLOAT             |
| Decimal                                | DECIMAL           |
| String                                 | STRING            |
| Boolean                                | BOOLEAN           |
| Date                                   | DATE              |
| TIMESTAMP                              | TIMESTAMP         |
| Bytes                                  | BINARY            |
| STRING (comma-separated, e.g. 'a,b,c') | ARRAY             |
| STRING (JSON, e.g. '{"a":"1"}')        | MAP               |

Iceberg types not listed in the table take their values as follows:

- `TIME` takes the hour/minute/second part of a date/time column, `UUID` is parsed from a string, and `FIXED` is written from a bytes column.
- The element type of an `ARRAY` and the key and value types of a `MAP` follow the type declared by the table schema, and the source string is parsed as that type (for example `'1,2,3'` written to `array<int>`, `'{"a":"1"}'` written to `map<string,bigint>`).
- `struct`, `variant` and structs nested inside `array`/`map` in the table schema are not written by the plugin: a task mapped to such a column fails and exits when it reads the first record.
- When the value of a row cannot be converted to the type declared by the column, that row is skipped and counted as dirty data instead of being written as `null`.
